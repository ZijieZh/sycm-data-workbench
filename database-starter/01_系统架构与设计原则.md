# 系统架构与设计原则

## 总体架构

```text
业务系统导出
    ↓
Excel / CSV源数据区
    ↓
文件盘点与批次校验
    ↓
字段清洗、标准化、业务打标
    ↓
DuckDB事实表 fact_*
    ↓
DuckDB分析表 mart_*
    ↓
只读MCP业务工具
    ↓
AI助手自然语言查询
```

## 各层职责

| 层级 | 职责 | 典型内容 |
|---|---|---|
| 源数据层 | 保存业务系统原始导出 | Excel、CSV、来源文件名 |
| 导入层 | 读取、清洗、校验、写库 | Python、pandas、DuckDB |
| 事实层 | 保存标准化后的明细事实 | `fact_sales_monthly` |
| 分析层 | 固化日常查询口径 | `mart_sales_monthly` |
| 审计层 | 记录批次、哈希、行数、状态 | `etl_import_batch` |
| 服务层 | 提供只读结构化查询工具 | MCP Server |
| 交互层 | 理解自然语言并组织结果 | AI助手 |

## 核心设计原则

### 1. 源数据可追溯

事实表保留来源文件、来源sheet、来源行号、导入批次和导入时间。任何汇总数字都可以定位到来源。

### 2. 业务口径集中管理

指标字典统一定义GMV、销量、成交人数、转化率等指标。分析表与MCP工具复用同一套定义。

### 3. 自然键保证唯一性

每张事实表明确业务自然键。例如月度商品表可使用“统计月份 + 店铺 + 商品ID”。重复数据在写库前完成识别、核对和处理。

### 4. 事实表与分析表分层

事实表保留标准化明细；分析表处理供应商拆分、状态筛选和常用聚合。AI助手优先调用分析表。

### 5. 校验先于写库

导入分成`validate-only`和`write-db`两个阶段。完整性、冲突和勾稽校验通过后进入写库阶段。

### 6. 查询服务只读

MCP以DuckDB只读模式连接，关闭外部文件访问，限制授权表、最大行数、执行时间和并发数。

### 7. 更新采用批次和快照

每次更新记录批次ID、源文件哈希、目标期间和质量结果。共享服务读取发布快照，写库流程与查询流程相互隔离。
