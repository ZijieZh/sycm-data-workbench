# 日常更新和运维流程

## 月度更新

1. 将新导出文件放入目标月份批次目录。
2. 运行文件盘点，核对文件数、sheet和目标月份。
3. 运行`--validate-only`生成质量报告。
4. 处理阻断项并重新校验。
5. 质量报告阻断项为0后运行`--write-db`。
6. 运行数据库验证和自动化测试。
7. 更新数据库地图、字段字典和覆盖范围。
8. 生成带版本号的只读快照。
9. 将快照发布到共享服务并执行MCP验收查询。
10. 记录批次ID、版本、发布时间和操作者。

## 备份与版本

推荐版本号使用：

```text
YYYYMMDD_HHMMSS
```

推荐文件：

```text
db/snapshots/business_20260901_103000.duckdb
db/manifest.json
```

`manifest.json`记录当前版本、数据库文件、SHA256、发布时间、数据覆盖范围和质量报告路径。

## 团队账号

每位同事建立唯一用户ID和独立Token。账号操作均记录操作者、时间和状态：

- 新增：生成一次性明文Token和个人接入包。
- 禁用：立即停止该Token访问。
- 恢复：重新启用现有Token。
- 轮换：生成新Token并更新个人接入包。
- 删除：移除离职或永久停用账号。
- 列表：查看用户ID、显示名、启用状态和更新时间。

## 服务启动

Windows共享电脑推荐使用计划任务并以SYSTEM运行：

- 触发器：系统启动时。
- 服务账户：SYSTEM。
- 运行级别：最高权限。
- 工作目录：MCP项目根目录。
- 日志：标准输出和错误输出写入独立日志文件。

日常检查包含：计划任务状态、监听地址、端口、数据库快照、Token存储、磁盘空间和最新审计日志。

## 故障定位

| 现象 | 检查顺序 |
|---|---|
| AI助手无连接器 | `mcp.json`路径、JSON格式、AI助手重启 |
| 连接超时 | 服务状态、监听端口、防火墙、公司网络 |
| 返回401 | Token状态、Authorization格式、Token轮换记录 |
| 服务未监听 | 服务日志、Python环境、数据库路径、计划任务结果 |
| 数据版本落后 | manifest版本、已发布快照、服务读取路径 |
| 查询数字异常 | 时间覆盖、选表、口径、自然键、汇总勾稽、数据库版本 |

## 每周巡检

- 服务自动启动状态正常。
- 端口仅监听约定地址。
- 防火墙范围与公司网段一致。
- Token用户与在岗人员一致。
- 审计日志持续写入并完成轮转。
- 最新数据库快照可读且哈希一致。
- 备份数量与保留周期符合约定。
- 磁盘剩余空间充足。

## 变更原则

字段、打标、指标和聚合规则的调整依次完成：业务确认、测试样例、脚本修改、历史回测、全量验证、文档更新和快照发布。
