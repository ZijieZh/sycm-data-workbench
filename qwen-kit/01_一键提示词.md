# 给千问办公的一键提示词

请使用千问办公制作并发布一个可公开访问、链接稳定的在线作品展示网页，作品名称为“生参数据工作台”。这是千问办公 AI 生产力大赛复赛网页，页面要让评审和公众一眼看懂：这个作品解决什么问题、如何使用、用户如何评价、已经产生了什么结果。

## 一、必须遵守的公开口径

- 页面所有公开品牌/店铺称呼统一使用“生参旗舰店”。
- 不得出现任何真实店铺名、真实店铺 ID、账号、密码、Cookie、Token、接口密钥、内部 URL、本机文件路径或真实业务截图。
- 不得出现任何已脱敏前的品牌名称，只使用“生参旗舰店”。
- 所有金额、商品名、商品编号、趋势和质量分数均标注为“虚构演示数据”。
- 不要编造用户评价。没有真实评价时，写“内部试用反馈位，发布前替换为真实反馈”，或展示“待补充”的明确占位，不要伪造姓名、公司和数字。
- 页面必须在桌面端和手机端正常显示，不能依赖登录才能打开。

## 二、页面结构

请制作一个信息密度适中、适合评审快速浏览的长页面，包含以下模块：

1. 首屏：作品名称“生参数据工作台”，一句话价值主张“从取数、建库到经营分析，形成可追溯的数据工作流”，按钮“查看 BI 演示”“查看项目仓库”。
2. 真实工作问题：说明原始痛点是重复点击、表格分散、口径不一致、无法追溯、分析难以下钻。
3. 解决方案全链路：页面取数 → 文件归档 → 写前校验 → DuckDB 事实表 → 指标建模 → BI 分析 → 行动输出。
4. 三款插件：通用取数 v0.1.12、竞店流失取数 v0.2.6、竞品流失取数 v0.3.5。说明它们操作页面可见控件，不读取账号凭证，不调用平台内部接口。
5. BI 在线演示：使用“生参旗舰店”作为虚构店铺，提供经营总览、多维归因、商品诊断、数据治理四个视图；至少支持周期和系列筛选，图表或指标随筛选变化。
6. DuckDB 数据库方法：源文件不覆盖、先校验再写库、事实层与分析层分离、查询默认只读；放出一段可读的运行命令。
7. 用户评价：单独一块展示真实反馈。若没有经授权的真实反馈，就使用“内部试用反馈待补充”占位，并说明发布前需要替换。
8. 实际成果：三款可下载插件、可运行的 DuckDB 示例模板、可交互 BI 演示、质量校验和 SHA-256 校验文件。
9. 使用路径：下载插件 → Chrome 开发者模式加载 → 登录有权访问的页面 → 小范围验证 → 导出文件 → 按模板校验入库 → 打开 BI 看板。
10. 页脚：作品名、虚构数据声明、项目仓库和 Release 链接。

## 三、视觉和交互要求

- 中文优先，标题清晰，避免营销口号堆砌。
- 采用深绿、珊瑚红、浅灰、亮黄少量点缀；视觉重点放在数据链路和 BI 看板。
- 页面首屏就出现作品身份和真实产品形态，不要做空泛的企业宣传页。
- 使用卡片、步骤轨道、指标、表格和图表组织信息，但不要让页面变成一堆互相嵌套的卡片。
- 交互至少包括 BI 视图切换、周期选择、系列选择、插件下载按钮和 GitHub 链接。
- 所有按钮都要有真实动作或明确锚点；不能保留空链接、假按钮或“敬请期待”。
- 页面加载后直接显示主要内容；移动端不得横向溢出。
